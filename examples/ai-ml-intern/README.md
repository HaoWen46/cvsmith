# Worked example: AI/ML internship

This synthetic application demonstrates the current workflow through a prepared, unsent application against `evals/fixtures/jd-sample/ml-intern-posting.md`; its reserved contact details, demo URLs, employers, results, and target are test data and must never be submitted as a real application.

## Artifacts

- `career-vault.md`: unchanged legacy source supplied to the candidate-evidence migration.
- `candidate-evidence/`: target-neutral evidence index and semantic detail documents derived from the legacy source without importing its target-specific omission decision.
- `jd-analysis.md`: source-anchored target contract.
- `../../evals/fixtures/resume-sample/resume.yaml`: target-specific projection.
- `resume.pdf`: current rendered artifact.
- `layer-reports/`: objective reports for the current PDF.
- `projection-report.md`: objective source-mismatch result plus the agent-review inventory.
- `eval-report.md`: final recommendation and remaining optional tradeoffs.
- `application-ledger.md`: exact prepared PDF and YAML identities with `applied: no`, no outcome evidence, and no causal learning.

`READY TO SEND` in this directory means the fictional candidate and records satisfy the scenario after treating the reserved values as the scenario's supplied records; it never means the fixture itself should be submitted.

The example is successful only when the evidence workspace represents the unchanged supplied source, the objective reports describe the current PDF, both scenario gates are met, the source scanner finds no objective mismatch, the final report has no required changes within that scenario, and the tracker never upgrades preparation into submission.
