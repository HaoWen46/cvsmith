# Field guide: software engineering

Prioritize shipped ownership, measurable system behavior, and operational judgment.

## Evidence order

1. Shipped product or infrastructure with users, traffic, data volume, reliability, or organizational reach.
2. Measured improvement with the mechanism that caused it: latency, cost, build time, errors, availability, or developer time.
3. Operational work: incidents, migrations, rollout and rollback, on-call, observability, and reliability.
4. Engineering leverage: testing, CI, tooling, review, platform, or documentation adopted by others.
5. Open-source or personal work with real users, contributors, or a technically distinctive artifact.

Name the stack where it explains the mechanism; use concrete system nouns and keep the recorded title intact.

Avoid framework inventories without evidence, vague full-stack labels, percentages without an anchor, and minor stints that dilute the stronger story.

Experienced candidates usually put education later; this renderer has a fixed section order, so state the limitation if it materially weakens the target rather than pretending it does not.
